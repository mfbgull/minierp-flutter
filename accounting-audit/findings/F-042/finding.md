# F-042 — Salary payment hint subtracts the same advance twice

- Severity: MEDIUM; status: FAIL, reproduced in the mounted salary-pay dialog.
- Root cause: `lib/features/employees/salary_pay_dialog.dart:421` sums `totalPaid`; line 422 separately sums `advanceCarryover`; line 430 computes `employee.salary - totalPaid - advanceCarryover`. Backend `Employee.ts:386` sums all active salary-payment amounts, including auto advances, into total_paid; `Employee.ts:551` returns remaining=max(0,salary−total_paid) and separately labels advance_carryover. The Flutter model preserves server remaining at `employee_models.dart:218`, but the hint ignores it.
- Independent expected result: monthly salary 1,000, prior-month advance already paid 200, no further payment: remaining salary **800**. The same 200 must not reduce salary twice.
- Backend evidence: the first `GET /api/employees/1/salary/history` in `accounting-audit/evidence/backend-run-fPHem1/results.json` returned September total_paid=200, remaining=800, advance_carryover=200, status=advance after the prior month's salary overpayment. `accounting-audit/evidence/flutter-payroll-api-fixture.json` preserves this exact row and source reference.
- Actual UI: `Already paid this month: Rs. 200.00 + Advance from previous month: Rs. 200.00 — Remaining Balance: Rs. 600.00`. The mounted test uses the backend financial fields unchanged and relabels only pay_period to the current month because the dialog defaults to today's date.
- Impact: the pay-salary hint understates what remains payable by the advance amount; a user following the hint could underpay. The audit did not submit a payment, so no actual payroll write or ledger corruption is attributed to this UI finding. The amount-entry default remains 1,000; the defective number is the displayed remaining-balance hint.
- Reproduction: `flutter test --no-pub accounting-audit/tests/flutter_reports_test.dart --reporter expanded`; scenario `F-042 salary remaining counts carryover only once`; expected remaining800 text absent and actual600 captured.
- Artifacts: `accounting-audit/evidence/flutter-salary-carryover-widget.json`, `accounting-audit/evidence/flutter-payroll-api-fixture.json`, `accounting-audit/evidence/flutter-report-regressions.log`, `accounting-audit/evidence/flutter-report-regressions.exit`.
- Recommended correction: use the server remaining amount (or subtract total_paid once), and phrase advance as a component of paid rather than an additional amount. Keep a widget regression for salary1000/advance200, another with partial top-up, and a fully covered month.
- Distinct from F-020: this is a client calculation error before the next payment. F-020 concerns backend advance-asset clearance and payroll expense after settlement.
