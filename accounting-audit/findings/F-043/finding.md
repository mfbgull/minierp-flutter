# F-043 — P&L expense categories omit the damaged-stock loss included in total

> Current assessment, 2026-10-26: this report preserves its historical audit snapshot. See [remediation status](../../remediation/STATUS.md) for current source verification, fixes, tests and remaining limits.

- Severity: MEDIUM; status: FAIL, reproduced using the same disposable lifecycle API response that passes the financial oracle.
- Root cause: `server/src/models/Reports.ts:440` builds category rows from only `expenses` plus `supplier_bills`, while line448 computes authoritative total expenses from all non-COGS expense GL accounts. Stock loss account7202 (and other non-operational-table expense postings) enters the latter but has no category row. `lib/features/reports/profit_loss_report_screen.dart:186` renders those rows under `Expenses by Category` without an unclassified/other row or incomplete-breakdown explanation.
- Independent expected: one damaged-stock unit at cost10 plus operating expense10 produces total expenses20. The displayed breakdown must explain both10 amounts (or disclose its narrower scope).
- Actual API: totalExpenses20, netProfit50, expenses=[{expense_category: Office Supplies,total:10}]. Actual mounted screen shows `Total Expenses Rs.20.00` and `Expenses by Category / Office Supplies / Rs.10.00`, with no damage-loss category or reconciling remainder.
- Financial impact: a user cannot reconcile the visible expense categories to total expenses and cannot see the inventory loss in the breakdown. Revenue210, COGS140, gross70, total expense20 and net profit50 are correct; this finding does **not** claim profit is wrong.
- Scenario source: `accounting-audit/evidence/oracle-run-AbsZeT/api-events.json`, first successful GET /api/reports/profit-loss with fromDate2026-09-01/toDate2026-10-31. The lifecycle purchases70@10, sells15@15, returns three units, resells two, writes off one damaged unit10, and records operating expense10.
- Reproduction: `FLUTTER_AUDIT_ORACLE=accounting-audit/evidence/oracle-run-AbsZeT/api-events.json flutter test --no-pub accounting-audit/tests/flutter_oracle_reports_test.dart --reporter expanded --tags known-defect`; scenario `F-043 P&L expense-category rows reconcile to expense total` expects20, observes10.
- Artifacts: `accounting-audit/evidence/flutter-pnl-breakdown.json`, `flutter-pnl-breakdown.log`, `flutter-pnl-breakdown.exit`; mounted Text output in `flutter-oracle-pnl-widget.json`, positive widget run in `flutter-oracle-replay.log` confirms actual display and refresh.
- Recommended correction: derive a complete GL-account expense breakdown or add an explicitly labeled reconciling category for GL expenses missing operational categories. Preserve category names without double-counting operational postings. Regression should mix operating expense, damaged/expired stock loss, payroll and supplier bill and assert displayed rows reconcile to the authoritative total.
