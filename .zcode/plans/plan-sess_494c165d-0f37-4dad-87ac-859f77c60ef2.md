# Persist PlutoGrid column widths locally across sessions

## Approach
Capture width changes from pluto_grid's public `stateManager.resizingChangeNotifier` (fires on every drag-resize), save them as a JSON blob in SharedPreferences keyed by screen, and re-apply saved widths after each screen's autofit pass. Local-only storage, same pattern as the existing `RecentItems` blob (`lib/features/search/recent_items.dart`).

## Changes

### 1. New file `lib/widgets/grid_column_widths.dart`
A small utility class, e.g. `GridColumnWidths`:
- **Storage:** single SharedPreferences key `grid_column_widths` holding `{ "<screenKey>": { "<columnField>": width } }`. Helpers: `loadFor(screenKey)`, `saveFor(screenKey, widths)`.
- **`attach({stateManager, screenKey})`** — full lifecycle helper:
  - Applies saved widths post-frame using `resizeColumn(column, saved − current)` (same mechanism as existing `autoFitPlutoColumns`).
  - Listens to `resizingChangeNotifier`; while an internal `_applying` guard is set (during restore/autofit), events are ignored — so only genuine user drags get persisted. Saves are debounced (~600 ms) so dragging doesn't write every tick.
  - Persists only data columns: skips hidden columns, renderer columns (status/actions), and system fields (`serial`, `id`, `actions`).

### 2. Shared mixin — `lib/widgets/pluto_grid_screen.dart`
- Add overridable `gridColumnKey` getter defaulting to the screen's `runtimeType`.
- Wire into the mixin's own `onLoaded` handler (~L458): run `autoFitPlutoColumns` under the guard, then apply saved widths (saved wins for touched columns, untouched columns keep autofit).
- Update `scheduleColumnAutoFit` (re-runs after every data sync ~L402) to finish by re-applying saved widths, so refreshes don't stomp user sizing.
- Covers all **21 mixin screens** (items, customers, purchases, users, roles, warehouses, physical counts…) automatically.

### 3. Retrofit the 9 direct-rendering screens
One-line `GridColumnWidths.attach(...)` in each screen's existing `onLoaded`, placed after its `autoFitPlutoColumns` call: sales, expenses, batch_management, general_ledger_report, expiry_report, trial_balance_report, cash_flow_report, batch_traceability_report.
Deliberately excluded: `sales_invoice_form_page.dart` — its line-entry grid has authored fixed widths by design.

### 4. Verification
- `flutter analyze` on all touched files.
- Manual check: resize a column on Items (mixin path) and on Batch Management (direct path), hot-restart / close-reopen the app, confirm widths restored; confirm untouched columns still autofit after data reload.

No server, database, or API changes (local-only storage). Stale entries from renamed column fields are harmless — lookups simply miss and those columns fall back to autofit.
