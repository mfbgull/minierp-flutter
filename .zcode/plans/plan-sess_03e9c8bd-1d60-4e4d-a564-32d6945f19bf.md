# Plan (final): Unified Payment Hub on the Payments screen

## Goal
Turn the **Payments screen into a unified payment / cash-movement hub for all currently supported payment-related transaction types** (customer payment, supplier payment, expense, salary payment, owner capital, owner withdrawal). Future types (bank transfers, loans, refunds, tax) are explicitly out of scope.

## Core design
Read-only **aggregation** over existing tables via `GET /payments/unified` (`getUnifiedPayments()`, `UnifiedPayment`). Creation stays in existing dialogs/modals (each posts its own GL entry) → no schema change, no duplicated `payments` row, no double ledger posting.

---

## Final data contract — `UnifiedPayment` (API)
`source` | `source_id` | `ref_no` | `date` | `amount` | `method` | `type` | `direction` | `party` | `status` | `description` | `sort_created_at`.
- **`amount`** is ALWAYS positive (absolute). Sign only via `direction`.
- **`direction` ∈ `in | out | unknown`** (now supports `unknown` for legacy invalid rows — see below).
- **`type` ∈ `customer | supplier | expense | salary | owner_capital | owner_withdrawal | unknown`**.
- **`unique_id` is NOT returned by the API.** It is a Flutter-only derived UI key: `String get uniqueId => '$source:$sourceId'`.
- Raw `supplier_id`/`customer_id` are **removed** from the CTE (semantic smell). `party` holds the counterparty/descriptor; `party_id`/`party_type` are a documented optional future addition, not in scope now.

## Backend — exact SQL structure
`normalizeUnifiedMethod` is implemented as a **TypeScript helper that emits a SQL `CASE` expression** (it is NOT an SQLite function):
```ts
const methodSql = (col: string) => `CASE LOWER(TRIM(COALESCE(${col},'')))
  WHEN '' THEN 'unknown' WHEN 'cash' THEN 'cash'
  WHEN 'bank' THEN 'bank' WHEN 'bank transfer' THEN 'bank' WHEN 'check' THEN 'bank'
  WHEN 'online transfer' THEN 'bank' WHEN 'online payment' THEN 'bank' WHEN 'raast' THEN 'bank'
  WHEN 'easypaisa' THEN 'mobile_wallet' WHEN 'jazzcash' THEN 'mobile_wallet'
  WHEN 'upaisa' THEN 'mobile_wallet' WHEN 'mobile wallet' THEN 'mobile_wallet'
  WHEN 'credit card' THEN 'card' WHEN 'debit card' THEN 'card' WHEN 'credit' THEN 'credit'
  ELSE 'other' END`;
```
`type` is a guarded CASE; `direction` is derived in a **nested CTE** (SQLite can't reuse a SELECT-list alias in the same list):
```sql
WITH unified_raw AS (
  SELECT 'payment' source, id source_id, payment_no ref_no, payment_date date, ABS(amount) amount,
         ${methodSql('payment_method')} method,
         CASE WHEN supplier_id IS NOT NULL AND customer_id IS NOT NULL THEN 'unknown'
              WHEN supplier_id IS NOT NULL THEN 'supplier'
              WHEN customer_id IS NOT NULL THEN 'customer' ELSE 'unknown' END type,
         COALESCE(customer_name, supplier_name) party, 'posted' status, notes description,
         COALESCE(created_at, payment_date) sort_created_at
  FROM payments
  UNION ALL
  SELECT 'expense', id, expense_no, expense_date, ABS(amount), ${methodSql('payment_method')},
         'expense', COALESCE(vendor_name, expense_category), status, description,
         COALESCE(created_at, expense_date)
  FROM expenses WHERE status='Paid'
  UNION ALL
  SELECT 'salary', sp.id, 'SAL-'||sp.id, sp.payment_date, ABS(sp.amount), ${methodSql('sp.payment_method')},
         'salary', e.full_name, sp.status, sp.notes, COALESCE(sp.created_at, sp.payment_date)
  FROM salary_payments sp JOIN employees e ON e.id=sp.employee_id
  UNION ALL
  SELECT 'owner_capital', id, capital_no, capital_date, ABS(amount), ${methodSql('payment_method')},
         'owner_capital', 'Owner', status, note, COALESCE(created_at, capital_date)
  FROM owner_capital WHERE status='posted'
  UNION ALL
  SELECT 'owner_withdrawal', id, withdrawal_no, withdrawal_date, ABS(amount), ${methodSql('payment_method')},
         'owner_withdrawal', 'Owner', status, note, COALESCE(created_at, withdrawal_date)
  FROM owner_withdrawals WHERE status='posted' AND kind='cash'   -- goods = inventory, not a payment
),
unified AS (
  SELECT *, CASE type
    WHEN 'customer' THEN 'in' WHEN 'owner_capital' THEN 'in'
    WHEN 'supplier' THEN 'out' WHEN 'expense' THEN 'out'
    WHEN 'salary' THEN 'out' WHEN 'owner_withdrawal' THEN 'out'
    ELSE 'unknown' END direction
  FROM unified_raw
)
```
- **`kind='cash'` is intentional**: `owner_withdrawals` `kind` ∈ {cash, goods}; goods withdrawals are inventory, excluded.
- **`sort_created_at = COALESCE(created_at, date)`** — every source has `created_at`; this guarantees a stable tie-breaker.
- **Shared predicate builder** `buildUnifiedWhere(filters)` produces `whereSql` (type / date range / search on `ref_no`,`party`,`description`). Data and COUNT queries both embed the *same* `whereSql`:
  - data: `SELECT * FROM unified ${whereSql} ORDER BY ${sortColumns[sortBy]??'date'} ${order}, sort_created_at DESC, source ASC, source_id DESC LIMIT ? OFFSET ?`
  - count: `SELECT COUNT(*) total FROM unified ${whereSql}`
- **sortBy whitelist**: `date|amount|type|party|ref_no` → actual col; `sortOrder` only `ASC`/`DESC`. No raw column interpolation.
- Controller `getUnifiedPayments` mirrors `getPayments` envelope `{success, data, pagination}`; `GET /unified` in `routes/payments.ts` (auth + `payments:read`) in `paymentsController.ts` + `Payment.ts`.

## Frontend
- `lib/data/models/unified_payment.dart` — `UnifiedPayment.fromJson`; `uniqueId` getter.
- `lib/data/repositories/invoice_repository.dart` — `unifiedPayments(PagedRequest)`.
- `lib/features/payments/payments_providers.dart` — `unifiedPaymentsProvider`, `unifiedPaymentsTypeFilterProvider` (`all|customer|supplier|expense|salary|owner_capital|owner_withdrawal`), page/limit/search/sort providers.
- `lib/features/payments/payments_screen.dart`:
  - "Record Payment" → **`New Payment ▾` dropdown** (6 items): Receive from Customer→`showRecordPaymentDialog`; Pay to Supplier→supplier picker→`showSupplierPaymentModal`; Record Expense→`showExpenseFormDialog`; Pay Salary→employee picker→`showSalaryPayDialog`; Owner Capital→`showOwnerCapitalFormDialog`; Owner Withdrawal→`showOwnerWithdrawalFormDialog`.
  - **Type filter chip row** (All / Customer / Supplier / Expense / Salary / Owner Capital / Owner Withdrawal).
  - Grid uses `unifiedPaymentsProvider`; `type` column shows label with in(out)/unknown color coding; amounts always positive; `unique_id` as row key.
  - **Row detail routes to the transaction's own detail**: `payment`→`showPaymentDetailDialog` (edit/delete); `expense`→expense transaction detail (reuse or lightweight read-only sheet); `salary`→**Salary Payment detail** (read-only sheet: ref, employee, date, amount, method, status + "View Employee" link) — NOT employee detail; `owner_capital`/`owner_withdrawal`→transaction detail (read-only sheet if none exists). Read-only where a source lacks edit = explicit business rule.
- Supplier/Employee pickers — small dialogs reusing existing `supplierProviders`/`employeeProviders` + `SearchableSelect`.
- **Invalidation helper** `invalidateCashMovementProviders(ref, source)` called **only after a successful write**: refreshes `unifiedPaymentsProvider`, legacy `paymentsProvider`, the source provider (`expensesProvider`/salary/owner-equity), and balance/dashboard providers.
- l10n (`en.arb`/`ur.arb` + generated): `paymentsNewPayment`, type labels, method labels (cash/bank/card/mobile_wallet/credit/other/unknown), picker + detail titles.
